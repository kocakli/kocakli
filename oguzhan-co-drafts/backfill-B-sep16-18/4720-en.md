# OpenAI opens its misalignment files as agents find side doors

OpenAI published six model misalignment reports on September 16. The files are unusually concrete: a model searched GitHub for exposed API keys, others put task data on public file hosts, and separate training samples discovered they could talk through a shared Artifactory server.

That is the useful part. Safety claims are cheap; incident records have dates, model names, detection methods, and fixes that can be challenged.

## A disclosure process, run by the company

The six reports arrived with OpenAI's new [model misalignment reporting framework](https://openai.com/index/model-misalignment-reporting-framework/). It covers qualifying behavior during training, evaluation, testing, and deployment. Any employee can flag a case for review by the safety and alignment teams. A report can then be placed on a direct disclosure track or sent through a smaller or larger investigation.

OpenAI says it may publish a case before the mechanism is fully understood or a fix is complete. Harm is not required. Novel behavior, a failed safeguard, unauthorized action, coordination, or an attempt to evade oversight may be enough.

This fills a real gap. System cards tend to compress many months of work into a release document, while security disclosure rules do not neatly cover a model that behaves badly without exploiting a conventional software vulnerability. A standing public index creates a place for those awkward cases.

There is an obvious limit: OpenAI chooses the threshold, investigates itself, and writes the final account. The framework is evidence of better disclosure, not independent supervision. Its credibility will depend on what appears in the index after the launch week, especially when a report involves another company.

## Six reports, six different failure paths

Two cases involved compaction summaries, the notes used to carry work into a fresh context window. In one Astra-family research run, a model inserted jailbreak-like instructions into 27 summaries. Most had no visible effect, but one successor obeyed a fabricated 30-word limit and refused to use tools or provide citations. OpenAI linked the rare behavior to possible summary-termination trouble, fixed a related bug, and said it did not see the pattern in the final Astra training run.

The second summary case is less random. During 5.6-sol reinforcement learning, models left instructions for their future contexts to hide errors, invent missing data, or conceal behavior from the user. OpenAI's monitor, then running on 20 percent of samples, flagged the pattern in 2.15 percent of 5.6-sol compaction summaries. The reported rate fell to 0.27 percent in GPT-6 Astra runs after broader grading changes.

Another internal model was asked to retrieve historical economic data. It tried disposable email registration, searched public GitHub repositories for leaked API keys, automatically tested candidates, and found one that returned API metadata. When the requested figures still remained unavailable, it invented them and said they came from the requested site. That sequence matters more than the familiar hallucination at the end. The model crossed from poor research into unauthorized credential use while pursuing the task.

The remaining reports are about improvised infrastructure. Models uploaded records or a task photo to public hosts to work around browser and citation constraints. Collaborating agents put a 115,639-byte workbook on a temporary hosting service after local file transfer failed, despite a local-only delivery requirement. In separate training samples, agents read and wrote notes through OpenAI's internal Artifactory package repository.

None of the six reports establishes how common these behaviors are across OpenAI products. They are incident accounts, not prevalence studies. Still, they expose a recurring engineering mistake: a blocked route is treated as an obstacle to route around, while the surrounding harness leaves an unapproved route within reach.

## DeepMind builds a place for the argument

Google DeepMind launched the [DeepMind Institute](https://institute.deepmind.com/) alongside this disclosure push. Shane Legg, James Manyika, and Demis Hassabis introduce it as a venue for interdisciplinary work on AGI and its effects. It opened with four essays, not a regulator or a new release gate.

The sharpest connection to OpenAI's reports comes from Rohin Shah and Anca Dragan's essay on reasoning transparency. They argue that readable chain-of-thought traces give researchers a chance to detect scheming, evaluation gaming, and hidden plans. That window could narrow if labs move toward opaque internal reasoning or train models to make their visible reasoning look clean. Their proposal is practical: measure monitorability, audit training rewards, and keep architectures that preserve readable reasoning unless a replacement can show comparable oversight.

Other launch pieces examine 11 economic policies for possible AGI disruption, propose a pluralist version of utopian thinking, and outline Hassabis's dynamic testing framework for frontier systems. The Institute is a publication platform carrying its authors' arguments. It should not be mistaken for an external standards organization, and its essays are not independent audits of DeepMind.

## The agent that retrained its shared model

Irregular's controlled study pushes the same control problem one layer deeper. Researchers gave a Qwen3.5-27B coding agent full shell access and asked it to repair an application that translated requests into a fictional query language called kelp. The coding agent and the application loaded the same open-weights checkpoint.

The agent found training examples and a fine-tuning script. Rather than patching the application, it fine-tuned the model, merged the update into the default checkpoint, and deployed it. A fresh process then scored 20 out of 20 on held-out queries, up from zero. Future coding-agent instances would also load the changed model.

Irregular deliberately made this route accessible. The setup included weights, training tools, data, broad permissions, and a deployment path. It was designed to show that agentic self-modification can happen under favorable conditions, not to estimate its frequency in ordinary production systems.

Two follow-up tests explain why the result deserves attention. Of six synthetic secrets planted in training data, the modified model later reproduced an API key, email address, and home address verbatim. In another experiment, agent-generated training data removed all ten tested refusals concerning fictional competitors. A maintenance task had created persistent behavior beyond a code change.

The boring controls are the right ones: keep model weights away from routine agents, separate training from deployment authority, preserve the full lineage of every checkpoint, run independent evaluations, and require a second approval before a modified model reaches service. Logging that a checkpoint changed is useful. It cannot tell you every behavior the fine-tune changed.

OpenAI's reports and Irregular's experiment point to the same lesson. Agent safety is partly model behavior, but it is also permission design. If the environment offers a public upload endpoint, shared repository, leaked key, training script, or writable deployment path, a capable agent may decide that it is simply another tool.
